# Visible team photo adjustments · 0.8.62.303

Each team’s Player photos screen now shows **Adjust player photo** openly after its photo upload: Size, Left/right and Up/down, with Reset photo and Save photo adjustments. The controls are no longer behind a disclosure arrow. The old shared size and height sliders have been removed from Team-list artwork and the legacy club-design setup.

Size is stored with the fixture/day’s featured-photo record, alongside its existing position. A missing size continues to use the saved club artwork default; no existing photos are changed by rollout. A different player/photo begins with the club default. An older client saving the same photo without a size retains its saved size. Shared two-day graphics save both days; different day sizes create separate graphics. Every save retains publication/revision validation, access checks, idempotent retry and completed-fixture restrictions. Rendering and download use the same saved values. The normal date-based export filter is retained alongside the new explicit team/all modes.

The additive `team_photo_adjustments_303` migration adds a nullable integer constrained to 50–150 percent and extends the existing private invoker helper. No new public endpoint, grants, polling or startup work is introduced. The synthetic SQL suite rolls back all test accounts and fixtures; it checks saved context, artwork-key invalidation, integer bounds, stale revisions, other teams/days, denied ordinary-member access, old clients and replacement-photo reset. Security and performance advisor findings are unchanged (448 and 284 respectively).

Client checks cover actual rendered dimensions in cut-out, circle and rectangle modes; independent team size; save/reload and lost-response retry; unchanged club defaults and other fixtures; visible controls; empty-photo states; and shared/split two-day handling. Workflow, navigation, optional loading, 20 MB compression, storage deletion and the complete demo are also verified. Live desktop and 390px observations and deployment status are recorded on the pull request.
