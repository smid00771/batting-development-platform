# Fast visual startup — 0.8.62.288

The initial HTML now paints a compact Mirelion shell without waiting for application JavaScript or the full stylesheets. A small entry module gives that shell a paint opportunity, then starts the application. Authentication and club access still finish before any private club content appears. Download/boot failures offer a reload retry, including failure to download the entry module itself; invitation/password callback URLs remain untouched.

Optional tool controllers load on first opening: Selection Room, fixture results, Selection Groups and their permissions, PlayCricket connection/import, club-week tools, season statistics, call credits, Socials and platform social settings. Their loading/retry state stays in the existing content area. Guards for unsaved work stay synchronous after a tool is loaded. Imports are shared, and late module completions cannot mount into a different account, club, screen or detached host. Socials remains navigable while its first download is pending.

Help content and the graphic font fallback move out of the main script. The font fallback loads only after the normal font URL fails. Returning-player reminders use a dependency-free saved-availability module; comparison/evidence/statistics code is imported only for an explicit analysis request. The previous one-shot snapshots, invalidation rules, selection validation, permissions and call lifecycle are preserved.

Independent profile/access/trial context requests run together and the duplicate initial access request is removed. Assist unread work, message/coaching badges and device upkeep wait for the first page to finish and a browser paint/idle opportunity. Mandatory product and identity checks are retained. Combined-product batting setup still has its existing required context fetches; this is not a complete split of the remaining app.js monolith.
